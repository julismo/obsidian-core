# Structure

This repository publishes a vault taxonomy and the reasoning behind it. The notes that
would live in these folders are not here. Folders with nothing public to show are held
open with an empty `.gitkeep`.

Read this file to understand where a note goes and why. Start browsing at
[Home](4%20-%20Index/Home.md).

## Why the numbers

Top-level folders are numbered so they sort by how they are used rather than
alphabetically. A thought enters at `1 - Rough Notes`, earns its way into
`0 - Knowledge Base`, and is reached again through `4 - Index`. Number 6 is
deliberately skipped so the personal boundary stays at 7 even as sections are added.

## 0 - Knowledge Base

The durable half of the vault, organised as inbox, areas, projects, resources, archive.

`0. Inbox` is a holding pen, not a home. Anything left there is unfiled work.

`1. Areas` holds standing context that is true across projects rather than owned by
any one of them. The decimal numbering is stable: `1.1` through `1.7` keep the same
meaning over time, so a link written a year ago still points at the right idea.
`1.4 Tools and Stack` is where working setup lives, including `Agent Setup` with its
reusable `profiles` and `templates`.

`2. Projects` gives every project an identical folder. `_project-template` is that
shape, kept empty and copied for each new one. The two-digit prefixes are a lifecycle:
`01` to `06` run from brief to validation, `90 - Internal` holds working material that is
not part of the deliverable, and `99 - Models` holds the reusable pieces. Numbers are deliberately
sparse so a stage can be inserted without renaming the rest. `00 - Agent Scaffold` is
the per-project automation setup, and `08 - Memory` splits durable notes into
`feedback`, `project`, and `reference` so retrieval stays predictable.

`_example-project` is the same shape with notes in it. The company in those notes is
invented; they exist so the conventions are visible rather than described. Read them in
order to see how a brief becomes a procedure, a triage row, a demo, and finally a check
somebody can tick.

`3. Resources` is reference material that is not tied to a project.
`Systems/Agent Patterns` separates `Global` setup from `Cross-Project` patterns and a
portable `Skill Bundle`.

`4. Archive` is for finished or abandoned work kept for the record. `_meta` holds notes
about the vault itself. A leading underscore marks a folder that is machinery rather
than content, so it sorts away from real notes.

## 1 - Rough Notes

Capture with no obligation to be tidy. `1. Daily Notes` is the default landing place,
`2. Newsletter` drafts writing in public, `3. Canvas` holds visual thinking, and
`4. Study` tracks courses through a repeated `_course-template` of phases.

## 2 - Source Materials

Notes about external material, split by medium so that provenance is obvious. In the
private vault these folders hold the files themselves. Here they are empty on purpose:
attachments are never published.

## 3 - Tags

Tags are documented, not improvised. Each folder defines a small vocabulary for one
dimension, so tagging stays a choice from a known list.

## 4 - Index

Hand-made entry points. Indexes exist so navigation does not depend on search or on
remembering file names.

## 5 - Templates

Flat on purpose. A template is either useful enough to sit at the top or it should not
exist.

## 7 - Personal

The same organising logic applied to personal life, kept structurally separate from
work. In the public mirror it is empty; personal material stays private.
