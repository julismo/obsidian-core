# Acceptance Checklist

Each line restates an outcome from the brief in a form somebody can check without
interpreting it. Invented example.

## Checks

- [ ] A route change recorded by dispatch is visible to planning the same working day.
- [ ] Every change in the log has a named owner or an explicit note that it has none.
- [x] Declined changes stay in the log with the reason attached.
- [ ] The dispatcher can complete intake without asking anyone how to do it.

## Not accepted by

Anything measured by how the tool feels, or by how many changes were recorded. Volume is
not an outcome.

## If a check fails

Reopen the matching row in [[_example-project/04 - Triage/Triage Log]] rather than fixing
it quietly. The record of what failed is worth more than the fix.
